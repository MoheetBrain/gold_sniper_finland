============================================================
0. ONE-SENTENCE PROJECT DEFINITION
============================================================
GeoArb_Finland is a software-and-research pipeline that uses Finnish public geology/geophysics data, AI/ML prospectivity modelling, and Tukes cadastre/legal filters to generate high-quality orogenic gold target packages in the Central Lapland Greenstone Belt, then decide whether to reserve, partner, consult, or kill the target.

This is NOT a mining project.
This is NOT physical gold panning.
This is NOT “satellite sees gold.”

This is a target-intelligence and prospect-generator project:

    public data + geology + ML + cadastre control + target memo + buyer outreach

============================================================
1. CORE THESIS
============================================================
The report’s core conclusion is:

    Finland first.
    Central Lapland first.
    Orogenic gold first.
    GTK geophysics/till geochemistry first.
    Tukes reservation / partner route first.

Why Finland:
- Good gold endowment.
- Central Lapland has major gold systems: Kittila / Suurikuusikko, Ikkari, etc.
- GTK has strong public geophysics and geochemistry.
- Finland has a reservation mechanism that may allow low-cost target priority before expensive exploration.
- Nordic-focused junior explorers and majors already care about this belt.

Why NOT pure satellite-first:
- Finland is covered by forest, lakes, snow, and glacial till.
- Direct optical alteration mapping with Sentinel/Landsat is weak.
- The strategy must pivot from “pretty satellite colours” to geophysics + structure + till geochemistry.

Why this still fits AI:
- The data is high-dimensional.
- Known deposits provide labels.
- Unknown land is mostly unlabelled, not truly negative.
- ML can rank structural/geophysical/geochemical convergence.
- The real edge is integrating public data faster and more systematically than traditional juniors.

============================================================
2. PROJECT GOALS
============================================================
Primary goal:
    Build a working AI-assisted prospectivity engine for Finland gold target generation.

7-day sprint goal:
    Produce a credible ranked target map and 3 target memos for Central Lapland.

30-day goal:
    Build a reproducible pipeline, run backtests, identify top open/reservable target candidates, and start expert/geologist/company feedback.

Commercial goal:
    Convert target intelligence into one of:
    - reservation + option/JV discussion
    - consulting to existing claim holders
    - data-room sale
    - partnership with junior explorer / geological consultant
    - royalty/NSR-style retained upside if legally possible

Hard success criteria:
    1. Known deposits rank high in backtesting.
    2. Top model outputs are not single-sensor hallucinations.
    3. Top targets survive cadastre/protected-land masking.
    4. Top targets have multi-layer evidence convergence.
    5. At least 5 plausible buyer/partner entities exist.
    6. A local geologist / consultant can review or validate cheaply.

============================================================
3. NON-GOALS
============================================================
This project does NOT aim to:
- Mine gold.
- Physically dig or sample without permission.
- Spend large personal capital.
- Replace professional geology.
- Claim that AI proves gold exists.
- Reveal exact target coordinates to companies without staged disclosure.
- Build a black-box hype map.
- Continue if validation/backtesting fails.

============================================================
4. STRATEGIC SPLIT: FINLAND FIRST, SAUDI SECOND
============================================================
FINLAND_BRANCH = claim/control experiment
- Better for legal priority and prospect-generator route.
- Worse for optical satellite visibility.
- Stronger for public geophysics and ML labels.
- Best initial sprint.

SAUDI_BRANCH = partner-led target-intelligence experiment
- Better exposed geology and satellite visibility.
- Weaker solo legal-control path.
- More likely to require local company/partner/licensing route.
- Keep as phase 2 after pipeline proves itself.

This architecture starts with Finland because the report’s execution logic values:
    target generation -> legal/cadastre route -> memo -> partner/JV

============================================================
5. MAIN DEPOSIT MODEL: OROGENIC GOLD
============================================================
Orogenic gold = structurally controlled gold systems formed in shear/fault zones during deformation.

What to search for:
- Major shear zones.
- Second-order splays off major structures.
- Fault bends / jogs / intersections.
- Reactive host rocks: iron-rich volcanic rocks, carbonaceous sediments, tholeiitic basalts.
- Magnetic destruction zones: places where hydrothermal fluids destroyed magnetite, causing magnetic lows.
- Till geochemistry anomalies: Au, As, Sb, Te, Bi, W, Cu, Co, Ni, S etc.
- Proximity to known deposits, but not simply copying known mined areas.

Central Lapland priority concepts:
- Sirkka Line / Sirkka shear zone.
- Kiistala shear zone.
- Kittila/Suurikuusikko analogues.
- Ikkari-style structural targets.
- Structural splays and intersections on open/reservable ground.

============================================================
6. HIGH-LEVEL DATA FLOW
============================================================

    1. Define AOI
       Central Lapland Greenstone Belt, Finland

    2. Download public datasets
       GTK geology, magnetics, gravity, EM, radiometrics, till geochemistry, deposits
       Tukes cadastre/reservations/protected areas if available
       DEM/SRTM/Copernicus elevation
       optional Sentinel/Landsat for context only

    3. Standardise all data
       common CRS, resolution, grid, extent, file naming

    4. Generate evidence layers
       distance-to-faults, lineament density, magnetic derivatives, geochem anomalies, lithology features

    5. Build labels
       positive = known deposits/occurrences
       unlabelled = unknown background
       avoid treating all unknown pixels as barren

    6. Train baseline model
       Random Forest / XGBoost first
       MLP/EIS Toolkit optional after baseline

    7. Backtest
       spatial cross-validation
       leave-one-district-out
       top-k area capture

    8. Generate prospectivity raster
       0-1 score for every grid cell

    9. Falsify targets
       remove single-sensor anomalies
       remove protected/claimed/unusable areas
       remove historical exhausted sites
       remove obvious artefacts

    10. Rank target cells
        top 20 candidates
        top 5 open/legal candidates
        top 3 target memos

    11. Commercial decision
        reserve / partner / consult / kill

8. TOOL STACK AND HOW TO USE EACH TOOL
============================================================

8.1 Google Antigravity
Role:
    Agentic coding environment / project orchestration.

Use it for:
    - Creating the repo skeleton.
    - Writing boilerplate Python scripts.
    - Running tests.
    - Maintaining task plans.
    - Browser-assisted documentation lookup.
    - Generating README updates and sprint checklists.

How to use:
    - Open the project folder as a workspace.
    - Create a Mission: “Build GeoArb_Finland data pipeline.”
    - Give it one script at a time, not the whole project.
    - Require it to write tests before modifying destructive code.
    - Never allow autonomous deletion or system-wide cleanup.
    - Keep all outputs inside GeoArb_Finland/ only.

Safety rule:
    Agent may read/write project files only.
    No rm -rf.
    No deleting Downloads/Desktop.
    No secret API keys in scripts.

8.2 JetBrains / PyCharm
Role:
    Serious Python IDE for editing, debugging, and running code.

Use it for:
    - Refactoring scripts.
    - Debugging raster/vector shape errors.
    - Managing virtual environments.
    - Running unit tests.
    - Git commits.

How to use:
    - Open GeoArb_Finland/ as project.
    - Configure Python 3.11+ environment.
    - Use src/ as source root.
    - Use notebooks for exploration, src/ for production code.

8.3 QGIS
Role:
    GIS visual brain. Map layers, inspect targets, produce figures.

Use it for:
    - Viewing GTK layers.
    - Checking CRS and overlays.
    - Visualising prospectivity rasters.
    - Styling target maps.
    - Preparing target memo figures.
    - Running EIS Toolkit plugin.

How to use:
    - Load AOI boundary.
    - Load evidence rasters.
    - Load known deposits.
    - Load Tukes cadastre/protected layers.
    - Add target cells and inspect manually.
    - Export high-quality map layouts.

8.4 EIS Toolkit / EIS QGIS Plugin
Role:
    Open-source mineral prospectivity mapping toolkit.

Use it for:
    - Prospectivity modelling.
    - ML layers inside QGIS.
    - Rapid geologist-friendly workflows.

How to use:
    - Install QGIS plugin if compatible.
    - Test on sample dataset first.
    - Use it as a parallel baseline, not the only model.
    - Compare EIS output against your own Python model.

8.5 Python
Role:
    Reproducible data engine.

Use it for:
    - Downloading/processing data.
    - Building evidence rasters.
    - Training models.
    - Running backtests.
    - Exporting target tables and maps.

Core libraries:
    geopandas       vector GIS data
    rasterio        raster IO
    rioxarray       raster + xarray workflows
    xarray          multi-dimensional raster stacks
    numpy           arrays
    pandas          tables
    scipy           filters/interpolation
    scikit-learn    Random Forest, metrics, CV
    xgboost         gradient boosting
    imbalanced-learn SMOTE/class imbalance
    shap            feature importance/explainability
    matplotlib      plots
    folium/geemap   quick web maps
    pyproj          coordinate transforms
    shapely         geometry operations

8.6 Google Earth Engine
Role:
    Satellite/context layer processing.

Use it for:
    - Sentinel/Landsat context imagery.
    - Cloud/snow-free composite generation.
    - DEM context.
    - Regional visual sanity checks.

Important:
    In Finland, satellite is secondary. Do not over-weight it.

8.7 GTK / Finnish geological data portals
Role:
    Primary evidence source.

Use it for:
    - Bedrock geology.
    - Mineral deposits/occurrences.
    - Aeromagnetics.
    - EM.
    - Gravity.
    - Radiometrics.
    - Till geochemistry.

How to use:
    - Download layers manually first.
    - Record all source URLs and metadata.
    - Build download scripts only after you understand file formats.

8.8 Tukes cadastre / reservation systems
Role:
    Legal/open-ground filter.

Use it for:
    - Active permits.
    - Reservations.
    - Protected/unavailable land.
    - Candidate reservation feasibility.

How to use:
    - Use manually first.
    - Later automate if WFS/API available.
    - Never assume reservation = mining right.
    - Always verify legal state before outreach.

============================================================
12. KILL CRITERIA
============================================================

Kill immediately if:
1. The model fails spatial cross-validation.
2. Known deposits do not rank in top 10% area.
3. Top targets are all on active permits/reservations/protected areas.
4. Anomalies depend on only one data layer.
5. Targets lack structural + geophysical + geochemical convergence.
6. No open/reservable target survives masking.
7. Tukes/reservation route is not legally usable.
8. No credible buyer/partner universe exists.
9. Local geologist review would cost too much or be impossible.
10. The project becomes pretty maps without commercial/legal pathway.

============================================================
13. CONTINUE CRITERIA
============================================================

Continue if:
1. Known deposits are captured in top 5-10% of ranked area.
2. At least 3 target clusters survive falsification.
3. At least one target has legal/reservation path.
4. Top target has 3+ independent evidence layers.
5. There are 5+ plausible buyers/partners.
6. A local geologist can review for a controlled fee.
7. The target memo reads like conservative geology, not AI hype.

============================================================
14. WHAT “GOOD TARGET” MEANS
============================================================

A good target is NOT:
    “The model says high probability.”

A good target is:
    A coherent area where multiple independent geological signals converge:
        - structural complexity
        - second-order fault/splay
        - magnetic destruction / geophysical anomaly
        - favourable lithology
        - till geochemistry/pathfinder support
        - not already claimed/protected
        - close enough to infrastructure
        - plausible buyer interest
